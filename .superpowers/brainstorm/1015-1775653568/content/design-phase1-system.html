Phase 1 Design — Section 1: Animation & Depth System

The CSS foundation everything else builds on

The Gap Today

PARTS View (Premium)
  • Gradient backgrounds (180deg dark→darker)
  • Multi-layer box-shadows (inset highlight + inset bottom + outer)
  • Text-shadow glows on labels
  • Hover lift (translateY -1px)
  • Param popup: cyan border + triple glow + backdrop blur + scanlines
Everything Else (Flat)
  • STEPS: flat bg, simple border, basic pulse animation
  • GRID: beveled borders are good, but no gradients, no text glows
  • E2S: no gradients, no inner shadows, minimal hover states
  • Transport: play button is flat black, no depth
  • Pattern list: functional but zero visual personality

Proposed: Shared Depth Classes

Reusable CSS classes that bring any element to "PARTS-level" quality

hw-panel

The PARTS-view gradient + multi-shadow combo. For buttons, cells, controls that should feel like hardware panels.

hw-recess

Sunken inset look. For grids, sequencer backgrounds, display areas — things recessed into the hardware chassis.

hw-panel:hover

Lifted state with brighter gradient + deeper shadow. Consistent hover across all interactive panels.

Proposed: Animation Primitives

Reusable @keyframes that theatrical moments build on

@keyframes glow-pulse

Box-shadow + opacity oscillation. For LED states, active indicators, breathing elements. Replaces the 4 different pulse animations currently duplicated.

@keyframes led-flicker

Subtle brightness jitter (opacity 0.85→1.0). Simulates real LED behavior. For idle ambiance on active parts, playing indicators.

@keyframes scan-sweep

Horizontal gradient sweep (left→right). For loading states, import progress, active scan lines. The signature "cyberpunk" motion.

@keyframes warm-up

Opacity 0→1 with slight color temperature shift (cold→warm). For boot sequence, element reveal, panel power-on.

Key Principle

No new CSS files — everything stays inline in index.html. The depth classes and animation primitives go into the existing <style> block near the top. Views adopt them by adding classes, not by rewriting their CSS from scratch. Existing GRID bevel styling is good — we enhance it, not replace it.
